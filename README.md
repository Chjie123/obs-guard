# obs-guard

面向 OBS Studio 的实时内容遮挡滤镜。在合成画面进入编码器之前完成目标检测，并对命中区域叠加可配置样式的遮罩。

滤镜作为 OBS 原生视频滤镜运行，输出直接进入 OBS 码流，因此对推流平台无差别生效——无需为抖音、哔哩哔哩、视频号、YouTube 分别适配。

---

## 1. 概述

直播场景中的违规风险往往出现在几帧之内：一个二维码、一件印有竞品标识的商品、一处不合规的背景贴纸。事后剪辑无法挽回，直接掐播代价又过高。

obs-guard 的处理方式是**事前遮挡**：在编码前识别目标，就地覆盖，直播不中断。

检测与渲染全部在本地完成，画面不出本机，不依赖任何云端服务。

---

## 2. 能力

| 能力 | 说明 |
|---|---|
| 检测区域 | 支持画面百分比与源画面像素两套坐标系，仅在该区域内检测与遮挡 |
| 模型 | YOLO 系列 ONNX 模型；输入尺寸从计算图读取，类别名从模型元数据读取 |
| 目标筛选 | 置信度阈值、NMS IoU、单帧目标上限、按类别名或索引过滤 |
| 遮罩样式 | 纯色、高斯近似模糊、马赛克；颜色、不透明度、外扩比例、边缘边距可调 |
| 跨帧平滑 | IoU 关联、指数平滑、疑似/锁定两级、消失后保持与淡出 |
| 失败策略 | `fail-open` 直通（默认）与 `fail-closed` 全屏遮挡可选 |
| 运行监测 | 面板内显示推理后端与模型信息，提供不依赖模型的遮罩自检 |

## 3. 安装

### 3.1 分发包安装

1. 完全退出 OBS Studio（含托盘图标）。
2. 解压分发包，双击 `install.cmd`，在用户账户控制提示中确认。
3. 启动 OBS Studio。

安装脚本会自行定位 OBS 安装目录、检查运行状态、复制文件并校验结果。若 OBS 安装在非默认位置，可指定路径：

```powershell
.\install.ps1 -ObsDir "D:\obs-studio"
```

### 3.2 手动安装

分发包采用 OBS 标准目录结构，将 `obs-plugins` 与 `data` 两个目录整体覆盖到 OBS 安装目录即可（默认 `C:\Program Files\obs-studio`）。

### 3.3 卸载

双击 `uninstall.cmd`。安装时生成的文件清单位于 `obs-plugins\64bit\obs-guard.manifest.txt`，卸载按该清单执行，不影响其他插件。

## 4. 使用

### 4.1 挂载

1. 选中需要保护的源，打开「滤镜」。
2. 点击 `+`，选择「违禁内容遮挡」。

挂载位置有两种，按场景结构选择：

| 场景 | 做法 | 覆盖范围 |
|---|---|---|
| 单摄像头 / 单采集卡 | 直接对该源添加滤镜 | 该源 |
| 多源合成画面 | 新建审核场景，将原场景作为「场景源」加入，再对该场景源添加滤镜 | 整个画面 |

滤镜应位于滤镜链首位。若其前方存在裁剪、缩放或旋转类滤镜，遮罩坐标将与画面错位。

### 4.2 自检

首次配置建议按以下顺序验证，两步均不依赖模型：

1. 勾选「显示检测区域边框」，画面出现品红色矩形，说明挂载与坐标正确。
2. 点击「测试遮罩」，检测区域内叠加三秒样本遮罩，说明渲染链路正常。

## 5. 参数

### 5.1 检测

| 参数 | 默认值 | 说明 |
|---|---|---|
| 启用检测 | 开启 | 关闭后画面直通，不再绘制遮罩 |
| 检测频率 | 10 fps | 每秒推理次数。遮罩始终逐帧绘制，降低该值只减少占用 |
| 推理不可用时 | 直通画面 | `fail-open` 停止遮挡并告警；`fail-closed` 全屏遮挡直至恢复 |

### 5.2 检测区域

| 参数 | 默认值 | 说明 |
|---|---|---|
| 坐标系 | 百分比 | 百分比不受分辨率变化影响；像素坐标系以源画面为基准 |
| X / Y / 宽 / 高 | 0 / 0 / 100 / 100 | 从画面左上角起算 |

> 使用像素坐标系时，若滤镜挂在「显示器采集」源上，像素坐标即屏幕坐标。

### 5.3 模型

| 参数 | 默认值 | 说明 |
|---|---|---|
| 模型路径 | 空 | ONNX 文件；输入尺寸自动读取，无需填写 |
| 推理设备 | 自动 | 优先 DirectML，不可用时回退 CPU |
| 置信度阈值 | 0.35 | 提高可减少误遮，降低可提高召回 |
| NMS IoU | 0.45 | 重叠框抑制强度 |
| 单帧最多目标数 | 32 | 上限 64 |
| 目标类别 | 空 | 留空表示全部类别；支持类别名或索引，逗号分隔 |

### 5.4 遮罩样式

| 参数 | 默认值 | 说明 |
|---|---|---|
| 遮罩方式 | 马赛克 | 高危内容建议使用纯色 |
| 颜色 | 黑 | 纯色模式下生效 |
| 不透明度 | 0.85 | 取值范围 0.05 – 1.00 |
| 模糊半径 | 16 px | 以 1080p 为基准，随分辨率等比缩放 |
| 马赛克块大小 | 16 px | 同上 |
| 框体外扩比例 | 0.10 | 防止目标边缘泄漏 |
| 额外边距 | 4 px | 与上项叠加生效 |

> 大区域高斯模糊在生成式模型下存在被还原的可能。对高法律风险内容，应使用纯色或高密度马赛克。

### 5.5 平滑

| 参数 | 默认值 | 说明 |
|---|---|---|
| 目标消失后保持 | 300 ms | 抵住检测间隔造成的闪烁 |
| 淡出时长 | 180 ms | 保持结束后的过渡时间 |

## 6. 模型准备

插件不内置模型。使用 Ultralytics 权重导出 ONNX：

```bash
pip install ultralytics onnx onnxsim onnxruntime
python tools/export_onnx.py --weights yolo11s.pt --imgsz 384x640 --check
```

`--check` 会输出输入尺寸、输出布局与类别表，用于确认模型可被正确解析。

关于输入尺寸：16:9 内容填入 `640×640` 方形输入会产生约 43% 的无效黑边，计算量浪费且有效像素密度下降。推荐使用 `640×384`（stride 32 对齐），在同等算力下获得更高的小目标召回。

插件支持三类输出布局，无需手工指定：

- `[1, 4+nc, N]`：YOLOv8 / YOLO11 标准导出
- `[1, N, 4+nc]`：转置导出
- `[1, N, 6]`：已内置 NMS 的端到端模型

## 7. 从源码构建

### 7.1 环境要求

- Windows 10 1909 及以上 / Windows 11，x64
- Visual Studio 2022 生成工具，含「使用 C++ 的桌面开发」工作负载
- CMake 3.20 及以上
- OBS Studio（安装包不提供头文件与导入库，需从已安装版本生成 SDK）

### 7.2 步骤

```powershell
# 1. 从已安装的 OBS 生成 SDK（头文件 + obs.lib）
.\tools\fetch-obs-sdk.ps1

# 2. 构建
.\scripts\build.ps1 -SdkDir .\sdk -NoOrt

# 3. 打包
.\scripts\package.ps1
```

`-NoOrt` 用于跳过 ONNX Runtime 下载，构建产物不含推理后端，适合先验证渲染链路。去掉该参数即构建完整版本，ONNX Runtime（DirectML 版）由 CMake 首次配置时自动获取，约 100 MB。

构建脚本优先使用 Visual Studio 生成器；若环境中不存在已注册的 VS 实例，会自动切换至 NMake 并手工装配 MSVC 与 Windows SDK 环境变量。

### 7.3 产物

```
build_x64\rundir\
├─ obs-plugins\64bit\obs-guard.dll
└─ data\obs-plugins\obs-guard\
```

`scripts\deploy.ps1` 可将产物直接部署到本机 OBS（需要管理员权限，且 OBS 需处于关闭状态）。

## 9. 已知限制

1. **取帧方式**：当前通过 staging surface 回读整帧后在 CPU 完成区域缩放，1080p 下单次约 3–5 ms。检测频率为 10 fps 时对帧时间影响可接受，但仍是主要性能开销来源。
2. **进程隔离**：推理运行在插件进程内的独立线程，渲染线程不等待推理，但不具备进程级崩溃隔离。
3. **坐标系绑定**：遮罩在滤镜输入帧坐标系中绘制。滤镜链前方的几何变换会导致错位。
4. **平台叠加层不可见**：礼物特效、平台贴纸、平台自动字幕在推流之后合成，插件无法感知，亦无法遮挡。
5. **仅解析检测头**：旋转框与分割输出尚未支持。
